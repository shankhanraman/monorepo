Authentication Labs
Complete Guide

A broad guide to starting, understanding, testing, and comparing every authentication implementation in this repository.

1. What is in this repository?

Each lab independently protects a small FastAPI users/profiles application. The labs share the application idea but use different ways to establish identity.

Simplest

API key

A static HTTP credential for scripts and services.

Browser standard

JWT + Keycloak

A React SPA signs in through Keycloak and sends a signed token to FastAPI.

Browser recommended

OAuth BFF

The backend performs OAuth and gives the browser an opaque session cookie.

Enterprise SSO

SAML

Keycloak sends a signed SAML assertion to FastAPI.

Machine identity

mTLS

A client certificate proves identity at the TLS boundary.

Corporate network

Kerberos

A browser uses a Kerberos ticket through Keycloak SPNEGO.

Lab warning: local HTTP, development secrets, seeded demo credentials, and permissive settings are for learning only.

4. Common startup lifecycle

1. Docker starts PostgreSQL and any identity infrastructure.
2. Copy .env.example to .env when required.
3. Create a Python environment and install requirements.
4. Run Alembic migrations.
5. Start FastAPI.
6. Start React, if the lab has a frontend.
7. Open the documented URL and test public/protected requests.

Most labs provide fastapi-seerver/scripts/setup-local-dev.ps1. Each lab's GETTING-STARTED.md gives manual steps and health checks.

6. Detailed request flows

JWT / OIDC with PKCE

React → Keycloak login → one-time authorization code
React → token exchange using PKCE → JWT
React → FastAPI with Authorization: Bearer JWT
FastAPI → verifies signature and claims → protected route

OAuth 2.0 BFF

Browser → /auth/login → Keycloak
Keycloak → /auth/callback with one-time code
FastAPI → server-to-server exchange using client secret
FastAPI → database session
Browser ← HttpOnly cookie; writes also require X-CSRF

mTLS

Client presents certificate during TLS handshake
nginx validates certificate against trusted CA
nginx forwards verified identity
FastAPI accepts protected writes
FastAPI is not publicly exposed, preventing forged headers

11. Security lessons

  • Authentication proves identity; authorization decides what that identity may do.
  • JWT decoding is not verification: check signature and claims.
  • Validate issuer and audience to reject tokens from another application.
  • Keep OAuth client secrets on the backend.
  • Use HttpOnly, Secure, SameSite cookies and CSRF protection for cookie sessions.
  • Store API-key hashes, not plaintext keys; support rotation and revocation.
  • Keep certificate verification at a trusted TLS boundary.
  • Production requires HTTPS, secret management, rate limits, audit logs, least privilege, and short-lived credentials.
