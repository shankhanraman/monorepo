How authentication works

credential arrives → server validates it → request gets an identity → protected route allows or denies

MethodValidation
API keyHash the key, find an active database row, then allow.
JWTVerify Keycloak signature, issuer, audience, and expiry.
OAuth BFFLook up the random session cookie; require CSRF protection on writes.
SAMLValidate the signed assertion, then issue a session cookie.
mTLSnginx verifies the client certificate before forwarding identity to FastAPI.
KerberosKeycloak validates the SPNEGO ticket and issues a JWT.

These labs primarily demonstrate authentication. A successful login is not authorization; the demos do not implement per-user ownership or roles.

Tests and troubleshooting

.venv\Scripts\python.exe -m pytest
npm test
npm run build
  • Docker errors: start Docker Desktop and confirm docker info works.
  • Missing tables: run alembic upgrade head in the lab backend directory.
  • Redirect URI errors: use the exact frontend port for the selected lab.
  • Keycloak not ready: wait 30–60 seconds, then run docker compose logs keycloak.
  • Reset everything: docker compose down -v deletes lab data.
